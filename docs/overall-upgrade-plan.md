# 知途整体升级路线

更新日期：2026-08-23

## 当前落地状态

本轮已完成第 1-3 轮的功能底座，以及第 6、7 轮的一部分：

- 登录、注册、分用途验证码、密码修改与本地密码找回已形成真实流程；学生和管理员默认账号通过集成测试。
- 所有核心页面与接口已统一要求登录，生产环境不允许使用默认 JWT 密钥，后端路由加载失败会直接暴露。
- 已新增目标、阶段、任务、收藏、竞赛参与、论文阅读库、错题复习、成果档案和内容关系数据结构。
- 首页已改为个人工作台，展示活跃目标、下一任务、截止时间和最近成果，不再使用静态竞赛与题目数组。
- 竞赛状态、课程章节、判题结果和论文阅读状态可以回写并推进关联任务；完成目标会自动生成成果记录。
- 竞赛详情支持结构化计划预览，用户确认后才写入数据库；没有 AI 配置时使用可执行模板。
- `npm test` 已覆盖注册、默认账号登录、权限、竞赛计划、收藏、论文阅读、成果、AI 计划确认和密码找回闭环。

尚未进入品牌视觉、复杂动效、移动导航、Monaco 拆包、公开成果页与生产邮件发送。下一轮应先补齐功能体验和错误状态，再开始视觉系统。

## 1. 结论

知途现在是一个功能型原型，不是一个形成稳定使用闭环的产品。它已经具备竞赛、课程、刷题、论文、AI、用户与后台等模块，但这些模块主要停留在“列表 -> 详情 -> 单点操作”，没有真正完成项目材料中承诺的“发现机会 -> 构建能力 -> 产出成果”。

建议不要继续把它定义成泛化的“一站式大学生知识平台”，而是收紧为：

> 面向大学生的竞赛成长工作台：从选择目标，到完成备赛任务，再到沉淀可展示的成果。

现有课程、刷题、论文和 AI 不需要删除，但必须围绕“目标”和“成果”重新组织。

## 2. 当前基线

### 已有基础

- Vue 3 + Express + SQLite 的完整前后端结构。
- 学生、教师、管理员角色与 JWT 登录。
- 竞赛、课程、论文、刷题、AI 对话、审核后台等页面。
- 课程章节进度、笔记、代码提交和 AI 反馈等局部能力。
- 当前生产构建可以通过。

### 主要缺点

#### P0：产品闭环不存在

- 首页展示用户数、课程数和论文数，但没有“我接下来要做什么”。
- 竞赛、课程、论文、刷题之间没有真实的数据关系表，也没有个性化推荐依据。
- 竞赛只有浏览和详情，没有收藏、参赛状态、组队、截止日提醒、材料清单和成果提交。
- 论文只有搜索与详情，没有阅读清单、收藏夹、标注、笔记、引用或关系图。
- AI 主要是聊天入口，没有把回答转成任务、学习路径、阅读卡片或可追踪计划。
- 首页竞赛与题目使用静态数组，和数据库内容可能不一致。

#### P0：定位过宽，价值表达过虚

- “竞赛、刷题、课程、论文，一个入口就够了”描述的是功能集合，不是用户收益。
- “AI 通识智研与算法赋能空间”等表述抽象，无法让学生立刻判断为何要使用。
- 七个一级导航入口权重相同，用户必须自己理解模块关系。

#### P0：视觉与动效没有形成品牌

- 当前界面是绿色、白底、细边框、居中卡片的常规教育后台样式。
- 标题使用中文衬线体，正文使用 Inter，气质偏传统内容站，与目标参考的粗体几何字、红黑高对比和强互动不一致。
- 动效只有淡入、缩放、页面位移和卡片上浮，没有滚动叙事、共享元素过渡、指针反馈、3D 状态变化或连续场景。
- 模糊色块只是装饰，没有表达产品状态或用户进度。

#### P1：关键流程存在“演示感”

- “忘记密码”仍是空链接。
- 多个页面吞掉请求异常，接口失败后页面会表现成空数据，而不是可理解的错误状态。
- 只有首页和 AI 等少数路由要求登录，其他核心内容可以通过直达 URL 绕过登录页，与“打开网页先登录”的要求不一致。
- 项目文档声称有报名、收藏、推荐、成长追踪等能力，但当前代码和数据模型未完整实现。

#### P1：工程质量不足以支持全面升级

- 没有自动化测试，`npm test` 目前固定失败。
- 后端启动时会静默跳过加载失败的路由，容易把严重错误伪装成正常启动。
- JWT 存在默认密钥回退，生产环境风险较高。
- 登录令牌存放在 localStorage，缺少刷新、撤销和设备会话管理。
- Monaco 编辑器生产文件约 3.8 MB，需要独立懒加载和资源预算。
- 缺少统一的 Loading、Empty、Error、Success 状态规范。

#### P2：可访问性和移动端不足

- 缺少全局 `focus-visible` 规范和 `prefers-reduced-motion` 降级。
- 侧栏在窄屏下没有完整的移动导航策略。
- 部分按钮依赖文字和颜色表达状态，缺少一致的语义和反馈。

## 4. 目标产品闭环

1. 学生选择一个竞赛、研究主题或技能目标。
2. 系统根据目标、剩余时间和当前能力生成阶段计划。
3. 每个阶段关联课程章节、练习题、论文和待办事项。
4. 学生完成任务后获得明确反馈，系统更新能力和风险状态。
5. 竞赛或项目结束后沉淀作品、代码、论文、证书和复盘。
6. 成果进入个人档案，为下一次推荐和成长分析提供依据。

首页只需要回答四件事：当前目标是什么、下一步做什么、哪里有风险、最近取得了什么成果。

## 5. 多轮升级计划

### 第 0 轮：产品定向与内容清理

周期：1-2 天。

交付：确定核心用户、核心场景和一句话价值；删除虚假承诺和占位功能；建立模块与目标的关系图；统一产品名称和自然中文文案。

验收：新用户 10 秒内能说清产品用途；所有首页 CTA 都进入真实流程；文档声明与代码功能一致。

### 第 1 轮：可靠性与登录基线

周期：2-3 天。

交付：统一登录前置策略；完成登录、注册、验证码、退出、密码修改和找回入口；补齐错误、空数据、加载和重试状态；修复静默异常；建立 API 与认证冒烟测试。

验收：学生和管理员账号端到端登录通过；未登录访问核心页面统一跳转；关键接口失败有明确反馈；自动测试可重复运行。

### 第 2 轮：信息架构与个人工作台

周期：3-5 天。

交付：将七个平级入口重组为“工作台、发现、学习、研究、成果”；首页改为目标、下一任务、截止日、继续学习、最近成果；教师和管理员使用独立后台壳层。

验收：首页不再展示无行动价值的平台数量；用户在两次点击内回到未完成任务；桌面和移动导航均完整可用。

### 第 3 轮：核心成长闭环

周期：6-9 天。

交付：新增目标、里程碑、任务、收藏、提醒、竞赛参与、作品和模块关联数据；竞赛可收藏、标记参赛、建立备赛计划和提交成果；课程加入检查点；刷题加入错题与复习；论文加入阅读清单、集合、笔记和标签。

验收：一个学生可以从竞赛详情创建计划，完成关联学习和练习，最后提交一个成果档案；所有进度来自真实行为而非静态数字。

### 第 4 轮：品牌视觉系统

周期：3-5 天。

交付：建立红、黑、白和中性灰的高对比色板；使用几何无衬线中文字体；重做字号层级、栅格、按钮、表单、列表、状态和图标；移除模糊色块和通用卡片堆叠；形成可复用设计令牌。

建议方向：主红 `#ff5043`、黑 `#161616`、纸白 `#f5f5f2`，中文使用思源黑体或 Noto Sans SC，英文使用 Manrope 或 Geist。参考目标站的方法，不复制其品牌字段和图形资产。

验收：登录、首页、列表、详情、学习、编辑器和后台属于同一视觉系统；移动端无文字溢出；字体加载失败时仍保持合理字宽和层级。

### 第 5 轮：叙事动效与 3D 交互

周期：5-8 天。

交付：

- 登录页：全屏品牌场景，表单从场景中展开，登录成功后通过遮罩或形态变化进入工作台。
- 首页首屏：一个全屏 Three.js 场景，视觉对象与“目标 -> 学习 -> 成果”三个状态关联，而不是随机漂浮。
- 滚动叙事：文本逐字/逐行进入，场景随滚动改变构图，关键数字和进度同步变化。
- 列表到详情：使用共享元素和标题连续过渡，减少页面跳断感。
- 微交互：磁性按钮、指针视差、按压反馈、筛选重排、任务完成状态动画。
- 导航：滚动时收缩，进入学习或编辑器时变成专注模式。
- 无障碍：提供 `prefers-reduced-motion` 和低性能设备降级。

实现建议：GSAP + ScrollTrigger 负责时间线，Three.js 只负责一个主场景，普通控件用 CSS transform/opacity。动画优先保持 60fps，避免频繁改变宽高和布局。

验收：动效能说明层级、位置或状态；首屏三秒内可交互；中端笔记本无明显掉帧；关闭动效后流程仍完整。

### 第 6 轮：把 AI 从聊天框变成执行层

周期：4-6 天。

交付：AI 可从竞赛详情创建结构化备赛计划；从论文生成阅读卡、问题和引用笔记；从错题生成复习任务；所有 AI 结果可编辑、确认并写入系统，不直接污染正式数据。

验收：至少三个 AI 场景能产生可追踪对象；用户能看到来源、修改结果并撤销；聊天不再是唯一入口。

### 第 7 轮：成果档案、后台和数据分析

周期：3-5 天。

交付：个人成果页展示竞赛、作品、代码、论文、证书和能力证据；教师可发布任务和查看进度；管理员维护分类、关联和内容质量；加入关键事件分析。

验收：成果页可公开分享；教师能识别掉队学生；管理员能追踪内容来源和审核历史。

### 第 8 轮：性能、安全与发布

周期：3-4 天。

交付：拆分 Monaco 和 Three.js；图片、字体和场景按需加载；补齐端到端测试；移除默认 JWT 密钥；限制上传类型；建立备份、日志、健康检查和部署流程。

验收：核心页面满足性能预算；登录、计划、学习、提交和后台审核有 E2E 覆盖；生产配置没有默认密钥；错误可定位和恢复。

## 6. 建议优先级

不要直接从第 5 轮动效开始。推荐顺序是：第 0 轮 -> 第 1 轮 -> 第 2 轮 -> 第 3 轮 -> 第 4 轮 -> 第 5 轮。前四轮给动效提供真实内容和状态，第五轮才能做出目标站那种“动效就是产品”的感觉。

如果时间有限，最小可用升级包是第 0-5 轮。AI 执行层、成果档案和生产治理可以进入第二阶段。

## 7. 核心指标

- 激活：注册后 10 分钟内创建第一个目标或收藏第一个竞赛。
- 行动：每周完成任务数、课程检查点数、有效代码提交数、阅读笔记数。
- 闭环：创建计划后完成至少一个阶段的比例。
- 留存：次日、7 日和 30 日留存。
- 成果：完成并发布成果档案的用户比例。
- 质量：接口错误率、页面空白率、判题成功率、AI 结果采纳率。

## 8. 下一轮开工范围

下一轮建议完成第 2、3 轮余项：目标详情与编辑、课程/练习加入目标、错题复习入口、论文标签检索、竞赛成果提交、完整错误与重试状态，以及教师侧进度查看。完成这些验收后，再进入第 4 轮品牌视觉系统。
